How releases are made

  1. Release notes are published on this page once CAB has approved the release.
  2. The release scope is frozen when the release branch is cut; later changes need the release manager's agreement.
  3. CAB reviews the release, the rollback plan and the deployment window.
  4. Deployment is a GitOps pull request; Argo CD applies it to production after approval.
  5. Rollback is by reverting the release tag in the GitOps repository.
  6. Known issues carried over are listed with their tickets so that support teams can find them.
  7. Squads monitor their dashboards for an agreed hypercare period after the release.

Checking what is deployed

The running image tag of a service shows which release it belongs to. For example:

oc -n chub-reserve get deploy reserve-engine \
  -o jsonpath='{.spec.template.spec.containers[0].image}{"\n"}'
# image tags follow the release name, e.g. r2026.09.<patch>
argocd app get claims-hub-prod --show-operation
